# HTTP-ответы Gateway: исправление и повторная проверка

Дата: 2026-10-22. Ветка: `safety-checker/-safety-analyzer`.
[Машинный отчёт](http-response-limits.json) содержит хеши реализации/датасета
и восемь контрольных прогонов. Реальная модель: **not_run**, её метрики отсутствуют.

## Исправление

Раньше `aiter_bytes()` мог распаковать сжатое тело, затем `bytearray.extend()`
копировал чанк, и лишь после этого проверялся размер. Лимит не предотвращал
выделение памяти под распакованные данные и слишком большой чанк.

Оба API теперь запрашивают `Accept-Encoding: identity`, до чтения тела
отклоняют Content-Encoding, кроме отсутствующего или единственного identity,
и читают `aiter_raw()` без распаковки. Content-Length проверяется заранее;
фактический размер проверяется независимо от него перед каждым добавлением
чанка в буфер. Максимум — 32768 байт; точная граница допускается.
При отказе response закрывается, новые чанки не запрашиваются.

Команды при нарушениях получают DENY/status=error/invalid_model_output,
model_result=null. CheckedExecutor не вызывает MCP Executor.
Для ошибок HTTP/чтения сохраняются прежние fail-closed коды.

## Проверки

- **421 passed, 2 skipped**: два live-теста не включены без настроенного inference.
- 61 новая регрессия: gzip-тело с распакованным размером 2 MiB, другие кодирования,
  составные/дублированные заголовки, некорректный/превышенный Content-Length,
  заниженная или отсутствующая длина, одиночные и накопленные oversized-чанки,
  точная граница, ошибки чтения/статуса, закрытие stream и отсутствие MCP-вызовов.
- Проверяется инвариант буфера: чанк, превышающий оставшийся бюджет,
  не доходит до `extend()`. У сжатых ответов число чтений тела равно нулю.
- Сетевые mock-ответы теперь возвращаются непрочитанными stream, как при HTTP.
  Контрольные провайдеры также используют stream; production-обхода для
  предварительно прочитанного mock-ответа нет.
- Ruff check/format и функциональный запуск Analyzer с локальной заглушкой прошли.
  Контрактные тесты используют настоящий код закреплённого SPAS Gateway,
  полный контекст и native Nimble преобразование; inference подменён.

## Контрольная оценка качества и стабильности

Набор quality-v1: 90 кейсов, пять повторов, seed=42; 450 анализов на профиль,
350 ожидаемых модельных обращений. Проверены оба протокола: всего 3600 анализов
и 2800 обращений к mock-провайдерам. Команды не выполнялись.

| Профиль | Model false allow | Общая false allow | False block | Ошибки | Нестабильные кейсы |
|---|---:|---:|---:|---:|---:|
| always-allow | 100% | 66.67% | 0% | 0% | 0% |
| always-deny | 0% | 0% | 100% | 0% | 0% |
| alternating | 60% | 40% | 40% | 0% | 77.78% |
| unavailable | 0% | 0% | 100% | 77.78% | 0% |

Показатели одинаковы для chat_completions и decisions. Все намеренные дефекты
обнаружены, gates профилей ожидаемо провалены. Обходов/расхождений правил — 0.
У alternating нестабильны все 70 модельных кейсов; у unavailable coverage =0%.
Результаты подтверждают работоспособность оценщика после изменения транспорта.

## Реальный inference: блокер

`bespokelabs/Bespoke-Nimble-9B` поддерживается кодом проекта. На момент проверки
не заданы SAFETY_GATEWAY_BASE_URL, SAFETY_GATEWAY_API_KEY и SAFETY_MODEL;
конфигурация среды не содержала секретов и выбранного runtime.
Локально нет CUDA и torch, а официальный Nimble scorer требует CUDA.
В проекте найдены примеры конфигурации, развёрнутое подключение не найдено.

Ни одного запроса к реальным весам не выполнено. Качество и стабильность Nimble
не подтверждены, контрольные результаты выше не являются её benchmark.
Для реального прогона достаточно доступного Gateway с подключённым GPU runtime;
CUDA на машине Analyzer при этом не требуется. Нужны URL и логический маршрут,
клиентский ключ вводится через настройки среды. Инструкция и команда оценки:
[gateway.md](../gateway.md#проверка-реального-inference).
