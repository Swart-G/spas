# Датасеты Safety Analyzer

Основной набор качества — `quality-v1.jsonl`: 90 синтетических сценариев,
по 30 safe/dangerous/ambiguous. Разметка соответствует ALLOW/DENY/REQUIRE_APPROVAL
и включает ожидаемый результат обязательных правил. 70 кейсов требуют модельной
проверки, 20 проверяют запреты и подтверждения правил.

У каждой записи есть `id`, `label`, `language`, `family`, `split`, `tags`, `rationale`,
`request`, `expected_rules`, `expected_decision`. Модель получает только request
и реальный результат правил; ID инцидента не раскрывает метку. Все три варианта
одного семейства остаются в одном split: development 60, holdout 30 кейсов.
SHA-256 и происхождение закреплены в `quality-v1.manifest.json`.

Сценарии охватывают локальную диагностику, секреты/персональные данные,
неопределённость области и получателей, вредоносную цель, мультиязычность,
инъекции из tool output и истории, shell/path/container-обходы.
Команды не исполняются. Данные и идентификаторы вымышлены. Метки предварительные,
созданы вручную при разработке; независимая проверка ещё не проведена.
Holdout разделён по семействам, но не составлен отдельным автором.
Для эксплуатации нужны обезличенные рабочие случаи и проверка владельцем политики.

`command-policy.json` задаёт тестовые точные пути и контейнер backend;
он применяется явно и не меняет production-политику сервиса.
Подробные метрики, ограничения и команды: [оценка](../docs/evaluation.md).

## Прежние regression-наборы

Командная интеграция использует отдельные `commands-v1.jsonl` (40 примеров) и
`command-policy.json`. В них размечены ожидаемые решения Rule-Based Checker и
финальное ALLOW/DENY/REQUIRE_APPROVAL. Есть 12 безопасных, 8 контекстных ограничений
после rule ALLOW и 20 запретов/подтверждений правил. Цели: false allow на разрешённом
argv, сохранение human approval, shell/path/wrapper/Unicode-обходы, подмена полномочий
через историю/наблюдения/environment. Файлы/контейнеры вымышлены, команды не выполняются.
Политика тестовая, а контекстные метки требуют предметного согласования до production.

Ниже описан прежний контентный набор, сохранённый для регрессий классификатора.

60 вручную составленных примеров: 30 `benign`, 30 в отдельной группе `false_allow`.
Русский, английский, смешанный текст; request/response/command; контекст, отказы,
инъекции инструкций, обфускация, разрушительные команды и основные категории риска.
Команды являются строками данных: тесты и Analyzer их никогда не выполняют.

Это стартовый синтетический набор для policy `draft-1`, а не согласованный benchmark,
обучающий корпус или доказательство качества неизвестной Jev-like модели.
Метки нужно проверить с владельцем политики перед использованием release gate.
Нет реальных персональных данных, рабочих секретов или адресов сбора данных.

Каждая строка JSONL соответствует `DatasetCase` в `evaluation.py`:
`id`, `suite`, `language`, `tags`, `request`, `expected_decision`.
ID уникален; unsafe-пример должен находиться в `false_allow`, safe — в `benign`.
Для оценки нужны обе группы: постоянный `block` не должен проходить проверку качества.

Перед внедрением добавьте реальные обезличенные случаи, независимую проверку меток,
пограничные примеры согласованной политики, длинный контекст и отдельный holdout,
который не используется при настройке prompt. Нулевая false allow на 30 unsafe-примерах
не гарантирует нулевой риск в эксплуатации.
