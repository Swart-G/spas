# СПАС - Система Предотвращения и Автоустранения Сбоев

Мультиагентная система для автоматического обнаружения,
диагностики и устранения сбоев и инцидентов.

## Запуск

На Linux с Docker Engine и Docker Compose выполните из корня проекта:

```bash
docker compose up --build -d
```

Сейчас сборка запускает LLM Gateway на `http://127.0.0.1:8008`.
Python и Claude Code входят в образ; конфигурация и аккаунты сохраняются в томе.
Все настройки и проверки доступны в едином SPAS TUI. На главном экране выберите
способ работы: подписки ChatGPT/Claude, платный API или Google Colab.
Маршруты, ключи доступа и журнал находятся в разделе Gateway:

```bash
docker compose run --rm tui
```

Подключение подписок, платного API, серверов Colab и проверки описаны в [llm/LLM.md](llm/LLM.md).
Раздел **Google Colab** показывает настроенные подключения. Выберите подключение
для изменения модели и GPU, запуска, проверок или остановки. Здесь доступны
Google OAuth, выбор GPU, скачивание и запуск модели, защищённый транспорт и маршрут
Gateway. Вход через официальное приложение Colab CLI не требует собственного
Google проекта или OAuth-клиента.

## Основная идея
- Orchestrator — основная модель, управляющая всем конвейером решения проблемы.
- Diagnostic Agent — агент, который анализирует и исследует состояние и окружение системы. Он собирает необходимые данные и определяет причину проблемы.
- Worker Agent — агент, отвечающий за устранение ошибки. Он получает предполагаемую причину, формирует план и исполняет его через executer_mcp.
- Executer MCP — интерфейс для выполнения действий над инфраструктурой.
- Memory — хранилище информации о прошлых инцидентах, документации и опыте работы системы.
- LLM Gateway — интерфейс доступа к LLM.

## Pipeline обработки инцидента
Incident
   ↓
Orchestrator
   ↓
Diagnostic Agent
   ↓
Diagnosis
   ↓
Worker Agent
   ↓
Plan
   ↓
Executor MCP
   ↓
Safety Checker
   ↓
Tools
   ↓
Execution Result
   ↓
Worker Agent
   ↓
Verification
   ↓
Resolved / Replan / Re-diagnosis

## Основные принципы
- Агенты напрямую не взаимодействуют с инфраструктурой.
- Доступ к LLM настраивается через Gateway, что позволяет использовать различных провайдеров.
- Мультиагентная система позволяет разделить процесс обработки инцидента, что делает поведение системы более стабильным и контролируемым.
