# CLI
Интерфейс командной строки для управления, настройки и тестирования СПАС.

Для Orchestrator доступны отдельные точки входа из корня репозитория:

```bash
python -m apps.cli.run_incident --stub
python -m apps.cli.run_incident --agent-factory my_application:build_agents
python -m apps.cli.demo_agents
python -m apps.cli.demo_agents --repair-fails
```

Используйте Python-окружение проекта (`uv run --locked --extra dev --extra colab ...`).
В `run_incident` обязателен ровно один режим: `--stub` или `--agent-factory`.
Фабрика — доверенная локальная функция без аргументов, синхронная либо асинхронная,
возвращающая `Mapping[RoleEnum, Agent]`. Она создаёт подключаемые реализации;
само ядро о них не знает. Модуль должен быть установлен или доступен в `PYTHONPATH`.
`--title`, `--description`, `--agent-timeout` и `--cleanup-timeout` настраивают прогон.

Вывод в stdout — JSON инцидента, диагностические ошибки идут в stderr.
Коды завершения: `0` — `RESOLVED`, `1` — обработка не завершилась успешно,
`2` — неверные аргументы или конфигурация подключения.

`demo_agents` самостоятельно запускает агентный HTTP-сервис на свободном порту
loopback. Diagnostic определяет состояние демонстрационного ресурса, Worker
выполняет исправление, Diagnostic проверяет его результат. Это реальное HTTP
взаимодействие и изменение локального состояния, без LLM и производственных систем.
`--repair-fails` оставляет ресурс неисправным: проверка даёт `FAILED`, повторного
Worker нет. Сервер закрывается после прогона. JSON включает инцидент, состояние
ресурса, число исправлений и последовательность обращений к агентам.
